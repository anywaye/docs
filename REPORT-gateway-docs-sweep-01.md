### The tripwire rule, stated once

A guard that cannot find its target is not a guard. A guard that cannot find its
*name* is worse: it is a word in a comment that means nothing, and it trains
everybody who reads that comment to expect the other meaning. That is why 29
occurrences outside the prose survived a sweep whose subject was the other 155.

## `services/guard.md` — the decision, and why

**Renamed to `services/gateway.md`.** The alternative was to keep the filename
and make the content unambiguous. Rejected, for one reason: **the sidebar is
autogenerated from the directory**, so keeping `guard.md` would have made the
site's own navigation the single place still asserting the old name, and
overriding the autogenerated label is more machinery than a rename.

**No redirect was added.** That is a measured decision, not a preference:

- `docs.cafaye.com` is **NXDOMAIN** (1.1.1.1), and no workflow in
  `.github/workflows/` deploys this site — the two files are `ci.yml` and
  `external-links.yml`. The URL has never been served, so there is no bookmark
  to preserve.
- Nothing in the fleet links to `/services/guard/`. A content grep for
  `services/guard` across every repository over `md, mdx, yml, yaml, json, ts,
  js, mjs, ex, exs, go, rb, py, rs` returns this repository's four inbound links,
  `pantry`'s own `/v1/services/guard` registry path (unrelated), and two
  `CHANGELOG.md` history lines.
- **A redirect is not free here.** Astro writes an HTML stub for a static
  redirect's *source* into `dist/` — `astro/dist/core/build/generate.js`,
  `body = redirectTemplate({...})`. So `dist/services/guard/index.html` would
  exist, and `tests/links.mjs` asserts that no redirect's source is also a live
  page. It cannot tell a redirect stub from a content page. Teaching it to is a
  change to a gate assertion, which this packet must not make.

**What it would break, had the site been live:** four inbound links on this site
(all fixed and named in the commit), the `#guard` anchor in
`architecture/topology.md` that the page links to (fixed), and any bookmark or
external link into `/services/guard/`. A redirect would preserve the last of
those. **If a future deploy puts the old path in the wild, add the redirect and
teach `tests/links.mjs` about Astro's stub in the same commit.**

## The database — whose it is, and why

The packet asked me to determine this by reading `identity`. **It is not
identity's, and it is nobody's.** Three measurements:

1. `grep -rn "CREATE DATABASE" gateway/src/` returns **nothing**. The gateway
   creates no database.
2. `gateway/docker-compose.yml` says so at length and gives the reason: *"`gateway`
   in `KIT_POSTGRES_DATABASES` would be a role and a database created for a
   service that never opens either — a name in a shared list describing no fact
   about the world."*
3. No repository in the fleet names `guard` in `KIT_POSTGRES_DATABASES` or
   `POSTGRES_DB`. `identity`'s is `identity`
   (`identity/docker-compose.yml:143`, DSN at `:224`); `courier`'s is `courier`;
   `muse`'s is `muse`.

So the example was demonstrating a database that cannot exist — and doing it in
a block labelled **measured** ("the sweep query above reported `guard` and
nothing else"), with `guard` sitting in a listing of real databases. After the
rename that is exactly the confident documentation of something that does not
exist, which `AGENTS.md` names as the failure mode to avoid.

The example is the best demonstration on the page, so it is kept and given a
name that exists: **`billing`**, with `courier` still the connecting role so the
two do not collide. `guard` comes out of the sweep listing, because a listing of
real databases cannot contain one nothing creates. The prose now says why the
name is not `gateway`, so a reader does not read the substitution as an error.

## What I found that the packet did not anticipate

**1. `muse` still declares a dependency named `guard`.** `muse/cafaye.yml`
carries `dependencies[].name: guard`, so `caf dev` and `pantry` read a service
name the rename removed — they will look for a service that does not exist.
`muse` was **not** in the packet's already-swept list, and its `master` is
`d4d5128`, which predates the rename.

Both pages that assert this dependency now state the fleet's meaning
(`gateway`) **and** the drift, in the sentence, rather than claiming agreement
that does not exist. `muse` is read-only from here per `AGENTS.md`. **This is
the successor's first real task**: sweep `muse`, and check its `openapi/v1.yaml`
(also matches `guard`).

**2. `pantry` may still resolve the old name.** `pantry/tests/api.rs:217` calls
`/v1/services/guard`. Whether that is a registry path derived from a manifest or
a literal is `pantry`'s to answer; note that a `wt-m39-gateway-rename-pantry-01`
worktree exists, so a packet may already have it.

**3. `architecture/topology.md:59` documents an environment variable the fleet
no longer sets.** It says *"`identity`, `billing` and `courier` each set
`POSTGRES_DB: <service>`, `muse` sets `POSTGRES_DB: muse`"*. Measured against
merged master: **`POSTGRES_DB` is deliberately NOT set by any of them.** Each of
those four compose files says so in a comment and provisions through
`KIT_POSTGRES_DATABASES` instead — `identity/docker-compose.yml:83` *"WHY
POSTGRES_DB / POSTGRES_USER / POSTGRES_PASSWORD ARE NOT HERE ANY MORE"*,
`courier/docker-compose.yml:104`, `muse/docker-compose.yml:89`. `POSTGRES_DB` now
names the cluster's *administration* database, not a service's.

**Not fixed here.** It is a real doc-vs-code contradiction on a page this packet
did edit, and it is not a rename — it needs its own packet with the gate run
against it. **It is named here so the next worker does not re-derive it.**

**4. Two smaller ones, also not fixed**, both on pages this packet edited:

- `troubleshooting.md:62-63` use `$GATEWAY` (was `$GUARD`) and **define it
